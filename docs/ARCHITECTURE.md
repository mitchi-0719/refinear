# ソフトウェアアーキテクチャ設計書 (Architecture & Data Flow)

このドキュメントは、Refinearアプリのコア機能（ファイルの解析・描画・再生）の設計方針とデータフローを定義する。実装時は必ず本設計に従うこと。

## 1. システム全体像
本アプリケーション最大の特徴は、**バックエンドの計算リソースを一切使わず、ブラウザ（フロントエンド）内で完結して `.mscz` ファイルの解析・描画・再生を行う**点である。
その実現のために、WASM（WebAssembly）と各種フロントエンドライブラリを組み合わせる。

## 2. データフロー（ファイル読み込み〜再生準備）

ユーザーが `.mscz` ファイルをアップロードしてからの処理の流れは以下の通り。

1. **ファイル受け取り (File API)**
   - ユーザーがドラッグ＆ドロップ、またはファイル選択で `.mscz` ファイルをアップロードする。
2. **WASMによる解析 (`webmscore`)**
   - 読み込んだファイルを `webmscore` (WebAssembly) に渡し、メモリ上でパースする。
   - ※サーバーには送信しない。ブラウザのローカルメモリ上で処理を完結させること。
3. **データの抽出**
   - `webmscore` インスタンスから、描画用の **MusicXMLデータ** と、メタデータ（パート情報やBPMなど）を抽出する。
   - `webmscore` は一部のMSCZに対して例外を投げず空のMusicXMLを返すことがあるため、パート数・小節数を検証してから後続処理へ渡す。詳細は [MSCZ変換互換性インシデントレポート](./MSCZ_COMPATIBILITY_INCIDENT_2026-08-07.md) を参照する。
4. **描画 (`OSMD`)**
   - 抽出したMusicXMLを `OpenSheetMusicDisplay (OSMD)` に渡し、SVGとしてブラウザ上にレスポンシブ描画する。
5. **オーディオエンジンの初期化 (`Tone.js`)**
   - 抽出した楽譜データをもとにオーディオエンジンを初期化し、各パートの音源（GainNodeなど）を準備する。

## 3. 状態管理設計 (Zustand)

コンポーネント間の不要な再レンダリングを防ぎ、サクサク動くUIを実現するため、状態管理は `Zustand` を用いて用途別にStoreを分割する。

### A. `useScoreStore` (ファイル・楽譜データ管理)
- **管理対象**: 読み込まれた `.mscz` ファイル本体、抽出された `MusicXML` 文字列、`webmscore` インスタンス、メタデータ（タイトル、作曲者など）。
- **役割**: 楽譜の表示に必要な大元のデータソースを保持する。

### B. `usePlayerStore` (再生状態管理)
- **管理対象**: `isPlaying` (再生中か), `currentTime` (現在の再生時間), `currentMeasure` (現在の小節), `bpm` (テンポ)。
- **役割**: ヘッダーのシークバー、再生ボタン、およびOSMDのカーソル移動を同期させる。毎秒更新される値があるため、Storeの購読(Subscribe)はコンポーネント単位で細かく最適化すること。

### C. `useMixerStore` (ミキサー・パート状態管理)
- **管理対象**: 各パートの配列 `parts: [{ id, name, volume, isMuted, isSolo }, ...]`
- **役割**: ドロワー内のミキサーUIと、裏側で動いているオーディオエンジン（`Tone.js` の GainNode）の音量制御を直結させる。

## 4. コア機能の連携に関する重要ルール

### 4.1. カーソルと再生の同期
- OSMDの描画更新（カーソルの移動）とTone.jsの再生タイマーは完全に同期させること。オーディオの `currentTime` を基準にしてOSMDのカーソルを進めるのがベストプラクティスである。

### 4.2. タップ発音機能（音取り）
- スマホ画面でのタップ発音を実現するため、OSMDの描画要素（SVGの音符ノード）に onClick イベントなどをバインド（または座標計算で最寄りの音符を特定）し、該当する音高（Pitch）を一時的に Tone.js のシンセに渡して発音させる仕組みを構築すること。

### 4.3. Web Audio API の制約（ユーザーインタラクション）
- ブラウザのセキュリティ仕様上、オーディオコンテキストは「ユーザーのタップやクリック操作」の直後に初期化・再開（`resume`）する必要がある。ファイルの読み込み時や再生開始時に必ずインタラクションを挟む設計とすること。

## 5. ディレクトリ構成方針

```text
├── app/                  # Next.js App Router (ページ、ルーティング)
├── components/           # UIコンポーネント (機能・ドメインごとに分割)
│   ├── layout/           # Header, Drawer 等
│   ├── player/           # OSMD Viewer, シークバー 等
│   └── mixer/            # ミキサーUI, ボリュームスライダー 等
├── store/                # Zustand Store (score, player, mixer)
├── lib/                  # 外部ライブラリのラッパー関数
├── constants/            # 固定値・既定値
├── hooks/                # カスタムフック
│   ├── webmscore.ts      # WASM初期化・解析ロジック
│   ├── audio.ts          # Tone.js 制御ロジック
│   └── osmd.ts           # OSMD描画設定ロジック
├── types/                # TypeScript 型定義ファイル
├── docs/                 # 開発ドキュメントファイル
└── data/                 # テスト用のデータとして.msczが置いてある

```
